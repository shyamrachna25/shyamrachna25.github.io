Data Engineering · ML

Meridian: API Migration Risk Tracker

Precision 1.000 · Recall 1.000 · 265 of 265 real migration edits found · +0.088 PR-AUC over baseline

Built a code intelligence tool that scans repositories at scale to identify API migration risks before they reach production. Used tree-sitter to parse 2,374 files across 22 repositories in 0.78 seconds-finding every real migration edit with zero false positives and all 1,059 package call sites with perfect precision and recall. The defect-prediction layer (trained on 30,000+ labelled commits with LightGBM, tuned via Optuna on time-ordered folds) beat the production baseline by +0.088 PR-AUC on held-out 2023 validation data. SHAP explanations make every prediction interpretable. The full pipeline is containerised in Docker and orchestrated with Airflow on GCP.

About

I'm drawn to the parts of engineering where data, infrastructure, and intelligence intersect - not because it's fashionable, but because that's where the most interesting problems tend to live and where solutions have real, measurable impact.

My path was more practical than academic. I started working at Quantiphi as an ML engineer before finishing my undergrad - got to see how production ML systems behave in the wild, including all the parts that rarely make it into papers. Then I spent a year at Eli Lilly owning data pipelines that couldn't have off days. That experience grounded a lot of my thinking about engineering quality and what it actually means to build something that works at scale.

I'm now at Northeastern filling in gaps, taking on research-adjacent projects, and figuring out what I want to build next. I tend to gravitate toward problems where the data infrastructure and the intelligence layer can't be treated as separate concerns - and where you have to understand both to build something good.

Outside of work: distributed systems internals, fairness in automated decision-making, and occasionally publishing things.
